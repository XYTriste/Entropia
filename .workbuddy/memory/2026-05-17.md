## DeepSeek Function Calling 修复（续）

### 问题与修复

**问题1：`query_classrooms() got an unexpected keyword argument 'classroom'`**
- 根因：`ai_service.py` 工具定义中参数名为 `classroom`，但 `classroom_tools.py` 函数签名中为 `class_room`（下划线）
- 修复：统一参数为 `classroom`（无下划线），同时支持单个字符串或逗号分隔的多教室

**问题2：`Attempted to access streaming response content, without having called read()`**
- 根因：第3步流式调用时仍传了 `tools=TOOLS`，DeepSeek 可能再次触发 tool_call，流式 `arguments` 分片无法正确解析
- 修复：第3步 `chat_stream()` 传入 `tools=None`

**问题3：AI 无法精确查询指定教室**
- 根因：工具定义缺少 `classroom` 参数，AI 无法理解"只查5-201"
- 修复：`TOOLS` 定义增加 `classroom` 参数；`query_classrooms()` 支持 `classroom` 过滤

### 修改文件清单

| 文件 | 修改内容 |
|------|----------|
| `app/services/ai_service.py` | 重写：统一参数名 `classroom`；第3步去掉 tools；system prompt 增加"不支持功能请诚实告知" |
| `app/tools/classroom_tools.py` | `query_classrooms()` 参数 `class_room` → `classroom`；支持逗号分隔多教室名 |
| `app/static/index.html` | 版本号 `v=56` → `v=57` |

### 技术细节
- DeepSeek Function Calling 参数名必须与 Python 函数签名完全一致（含下划线），否则 `**kwargs` 展开时报 `unexpected keyword argument`
- 工具参数定义为 `type: "string"`，AI 可能返回单个名称或逗号分隔名称，服务端需做 `split(",")` 兼容
- 两阶段调用架构：第1步非流式检测 tool_call → 执行工具 → 第3步流式（tools=None）返回最终回复

## DeepSeek `'str' object is not callable` 修复

### 问题与修复

**问题：`'str' object is not callable` 错误**
- 根因1：`chat_non_stream()` 中 `await response.text()` — httpx `response.text` 是属性（str），不是方法，调用 `()` 会报错
- 根因2：`make_sse()` 用 f-string 拼接 JSON 字符串，JSON 中的 `}` 会被 Python f-string 解析器误认为 f-string 结束符，导致 SSE 格式损坏
- 修复1：`ai_service.py` 第128行 `await response.text()` → `response.text`
- 修复2：`make_sse()` 改为字符串拼接 `"data: " + json_str + "\n\n"`，不用 f-string
- 修复3：`chat.py` 第189、252行 `json.dumps({'type': 'done'})` 语法错误 → 改用变量 `done_chunk = json.dumps({"type": "done"})`

### 修改文件清单

| 文件 | 修改内容 |
|------|----------|
| `app/services/ai_service.py` | `chat_non_stream`: `await response.text()` → `response.text`；`make_sse`: f-string → 字符串拼接 |
| `app/routers/chat.py` | 修复两处 `json.dumps({'type': 'done'})` 语法错误 |
| `app/static/index.html` | 版本号 `v=63` → `v=64` |

### 技术细节
- httpx `AsyncClient` 的 `Response.text` 是 `str` 属性，不是 async 方法，切勿加 `await` 或 `()`
- Python f-string 中用 `{...}` 包裹表达式，若拼接的字符串本身含 `}`，会导致解析歧义，应改用 `+` 拼接
- DeepSeek 模式已验证正常：工具调用 → 返回数据 → 模拟流式输出，全程无报错
