## 修复教室查询中固定监考老师过滤逻辑

**问题：** 用户测试"5-201的周一监考情况"，固定监考和流动监考显示了"许多老师的姓名"，但用户只需要"在这个时段内在这个教室内监考的教师姓名"。

**根因：** `ExamTeacher` 模型有 `classroom_id` 字段（关联到特定教室），但代码没有根据这个字段过滤，导致显示了某场考试的**所有**固定监考老师（可能分布在多个教室）。

**数据模型分析：**
- `ExamTeacher.classroom_id`：固定监考老师关联的教室ID（第64-69行）
- `ExamTeacher.role`：角色（`FIXED`=固定监考，`PATROL`=流动监考）
- 固定监考老师是分配到**特定教室**的，不是整个考试

**修复内容：**

修改第142-147行的逻辑，只添加 `classroom_id == cid` 的老师：
```python
# 修复前（错误）：显示所有固定监考老师
fixed_teachers = []
if exam.teacher_assignments:
    for et in exam.teacher_assignments:
        if et.teacher:
            fixed_teachers.append(et.teacher.name)

# 修复后（正确）：只显示在**这个教室**监考的老师
fixed_teachers = []
if exam.teacher_assignments:
    for et in exam.teacher_assignments:
        # 只添加分配到这个教室的固定监考老师
        if et.classroom_id == cid and et.teacher:
            fixed_teachers.append(et.teacher.name)
```

**状态：** ✅ 已修复、提交并推送到 GitHub，后端服务已重启

**逻辑说明：**
- **固定监考**：只显示在**指定教室**监考的老师（过滤 `classroom_id == cid`）
- **流动监考**：显示该时段的流动监考老师（流动监考是"巡场"，不固定于某个教室）

## 修复多教师查询时的AI幻觉问题

**问题：** 用户输入"查一下所有李姓老师的监考情况"，AI调用 `query_teacher_assignments` 工具（参数 `teacher_name="李"`），匹配到4位老师：李婷、李昂、李美长、李微。

但AI的行为是：
1. 展示第一位老师（李婷）的详细安排（6场）
2. 对另外三位老师（李昂、李美长、李微）直接断言"暂无监考安排"——**这是幻觉**，因为工具根本没有查询这三位老师的安排
3. 用户追问"李昂老师的"时，AI再次调用工具查询李昂，返回"暂无监考安排"

**根因分析：**
1. **工具设计缺陷：** `query_teacher_assignments` 在匹配到多位老师时，只返回第一位老师的完整数据，其余老师只是名字列表（`ambiguous` 字段）
2. **AI推理缺陷：** AI从"工具只返回了李婷有安排"推断出"其他老师没有安排"——这是典型的基于不完整数据的错误推断
3. **提示词缺陷：** 没有明确告知AI"匹配到多位老师时，工具只返回第一位老师的数据"

**修复内容：**

### 1. 修改 `app/tools/teacher_tools.py`
- 重构查询逻辑：遍历所有匹配的老师，对每个老师都查询其完整监考安排
- 新增内部函数 `_query_single_teacher()` 处理单个老师的查询
- 返回结构新增 `teachers` 数组，包含每位教师的完整数据：
  ```python
  {
      "found": True,
      "matched_count": 4,
      "teachers": [
          {
              "teacher": {...},
              "assignments": [...],
              "patrol_slots": [...],
              "total_assignments": N,
          },
          ...
      ],
      # 保留向后兼容的字段（指向第一个教师）
      "teacher": {...},
      "assignments": [...],
      ...
  }
  ```

### 2. 修改 `app/static/js/app.js`
- `_renderTeacherAssignments()` 方法重构：
  - 支持 `data.teachers` 数组（多教师查询结果）
  - 为每位教师渲染独立的卡片和表格
  - 多教师查询时显示汇总信息（共找到X位教师，Y位有安排）
  - 保持向后兼容（如果只有 `data.teacher` 字段，按原来的方式渲染）

### 3. 修改 `app/services/ai_service.py`
- 更新工具描述：说明支持模糊匹配，返回所有匹配教师的完整数据
- 更新系统提示词：
  - 添加"多教师查询规则"：明确告知AI工具会返回所有匹配教师的完整数据
  - 禁止AI基于不完整数据推断其他教师的安排情况
  - 更新追问处理规则：如果之前已查询过且结果中包含该教师数据，可直接基于已有数据回答

## 重构 AI 提示词结构

**问题：** `ai_service.py` 的 system message 越来越长（~66行），规则堆砌反而降低 AI 遵守效果。长提示词中的"中间迷失"问题导致核心指令被忽略。

**重构方案：**
1. **精简 system message** 到约 15 行（原来的 1/4）：只保留核心角色定义、工具触发条件、1 个关键示例
2. **参数提取规则移入工具 description**：AI 决定调用哪个工具和如何填参数时一定会看 description，比埋在 system message 里有效得多
3. **保留代码层空结果拦截**：`stream_chat` 中已有空结果直接返回逻辑（不依赖 AI 遵守规则）

**同时修复的 Bug：**
- `"role": "assitant"` 拼写错误（少了一个 `s`），应为 `"assistant"`，原拼写错误会导致 OpenAI API 返回 400 错误

**改动文件：** `app/services/ai_service.py`
- TOOLS 定义：description 字段增强，包含参数提取规则
- system_message：从 ~66 行精简到 ~15 行
- 修复 `"assitant"` → `"assistant"`（第338行附近）

**提交：** `0fb304a` - "重构AI提示词：精简system message，将参数规则移入工具description，修复assitant拼写bug"
**状态：** ✅ 已提交并推送到 GitHub

**设计原则（后续参考）：**
- 规则放在最靠近执行点的位置（参数规则→工具description；空结果处理→代码层拦截）
- 负面指令（"不得..."、"禁止..."）效果远不如正面指令
- LLM 不会真正遵守长篇"强制规则"，代码层拦截才是最终保障
